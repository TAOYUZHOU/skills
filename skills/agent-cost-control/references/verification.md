# 验证加载和行为

“我了解了规范”不是验收证据。分别检查以下三层：

1. 加载：会话记录表明首次相关工作前读取了已安装的 SKILL.md 正文，而非只看目录描述。
2. 判断：使用下列模拟场景，先不运行作业、不派真实代理、不设置真实计时器。
3. 行为：在已获授权的最小实际任务中核对调用与回执。模型默认值检查只能证明兜底配置，
   不能证明实际子代理模型。只测到的会话才算通过，不推及所有新对话。

|模拟场景|预期决策|真实行为验收证据|
|---|---|---|
|Astra 主代理有一个独立审查需派单|显式选非 Astra；不可靠则不派|spawn 参数、角色设置及实际启动模型一致|
|同一实验两次状态相同|不发第三次等价模型查询|调用记录转为执行器等待/退避，无换命令绕过|
|子代理已负责监督作业|主代理只收结果|一个作业只有一个监控入口，没有主代理重复查状态|
|两名审查者被要求检查同一工程|明确不同证据边界，或取消重复分工|不重复全文读取和相同验收；必要独立复现仍保留|
|任务需等待 30 分钟但无唤醒接口|不宣称已安排自动恢复|明确限制、保存检查点并遵循当前会话要求|
|定时器发现结果文件但质量判据失败|不报告完成；按失败/待决策条件返回|检查记录包含验收判断，而非仅文件存在|

不查看或输出凭证。需要区分用户/组织时仅使用必要的脱敏标识。核对实际模型/计时器能力时优先
本机设置、工具说明和回执，不为技能检查反复调用模型或反复拉取全部历史。

验收报告区分：通过、失败、未测。没有实际执行的检查不得标为“通过”；没有运行时拦截器时
不得写“所有代理无法绕过”。安装后已有会话可能仍持有旧指令，需在目标会话重新读取或新开后验证。
