# HARP 长时行为轨迹图谱

读者点开任一步，应能回答三个问题：agent 当时知道什么，选择了什么行动，什么证据使它继续、转向或停止。用读者的语言解释，保留原始编号。适用于运行复盘，包括 DOE 建模、CV 修复及其他跨多次行动的研究任务。

## 读取工作区

定位用户授权的工作区或冻结副本，记下路径、版本或采集时间。优先选择能解释策略变化的案例，例如同一审阅反复退回、有分支的假设比较、交付失败后重做证据交接。耗时和日志条数只能作为筛选线索。

对于包含 .state 的 HARP 工作区，可运行以下命令生成私有中间材料。采集器在临时目录复制 SQLite 主文件及已有 WAL 后查询，临时磁盘要能容纳二者。若复制期间数据库变化，请使用一致备份。正在变化的工作区要标明采集时点，各文件可能属于不同版本。

```sh
python3 scripts/collect.py /path/to/workspace /tmp/new-evidence.json
```

核对候选工作图的审批记录、计划状态、策略实体中的假设、干预、结果及审阅反馈。需要时读取对应的 review、manifest 和交付物。碰到其他存储版本，可用相同证据口径直接整理。采集器保留原始材料，交付前摘取必要内容。

## 重建与解释

- Plan DAG 取显式依赖；Strategy Tree 取同一计划内的 parent_attempt_id。按真实父级组织分叉；时间排序不构成依赖。替代关系、时间顺序或其他联系需单独标识。只在确有运行证据时绘制尝试。
- 标明图快照、纳入范围、缺失和未决证据。候选方案可能被驳回；说明各节点原意、驳回理由、是否入队。节点 ID 跨快照复用时结合图版本绑定尝试；无法唯一定位时说明缺口。区分 agent 自述、审阅裁定和独立复验。
- 给每次尝试起一个描述决策的短标题。连起当时的问题、采取的行动、观测结果和后续影响。保留不成功和未派发尝试。未知内心动机不能写成事实。用原始记录 ID、路径或短引文支撑关键判断。比较多个任务时将工作流成功与科学指标改善分别解释。

## 制作离线图谱

把整理后的材料保存为 JSON 数组。每项对应一个工作区或明确命名的快照。同一工作区有多份图时，可给每个计划附上 snapshot 字符串，按实际快照顺序排列，保留上下文和被退回的节点。结构见下例（字段内容为示意）：

```json
[{"title":"案例","source":"快照路径及时间","summary":"研究问题、范围和最终状态","plans":[{"id":"P1","title":"生成候选","summary":"计划目标、审阅决定和实际结果","depends_on":[],"attempts":[{"id":"A1","parent":"","title":"核对退回原因","summary":"行动与反馈","status":"failed","evidence":"A1；实际回执的摘录或路径"}]}]}]
```

```sh
python3 scripts/render.py cases.json atlas.html
```

让读者可在全局图与节点详情间来回查看。交付前将节点、依赖、尝试数与源记录核对，抽查分叉与失败路径，在浏览器验证阶段、计划及尝试的入口。引用研究结果时写明对应的计分合同与独立验证范围。仅经授权才上传运行材料。
