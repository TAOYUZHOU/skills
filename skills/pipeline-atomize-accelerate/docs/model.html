拆到不能再拆，再在容量里取 Pareto

常驻消重复 IO。把复合阶段切成原子，在一元资源上连续 stream。 只拆当前瓶颈。瓶颈原子无法再拆时，程序在这组资源上理论效率最优。 硬件 FLOPS / 内存 / 显存决定哪些旋钮可行；可行集上的通量–墙钟前沿才是 Pareto。

最优是一句停机条件，不是一种感觉

理论效率 ≠ 容量 Pareto ≠ 已落地调度。 把非 GPU 工作写进 \(T_{\mathrm{gpu}}\)、或把共享库上的两段活画成可并行，都会造出假前沿。

常驻 原子与 stream 停机 fill 预算 Gantt Preflight 核比 \(\kappa\)

1 · 常驻进程降低多次推理重复 IO

权重、分词器、CUDA context、HTTP session、索引：冷启动 \(T_{\mathrm{io}}^{\mathrm{cold}}\) 每个进程生命周期付一次。 热路径只该剩 \(T_{\mathrm{io}}^{\mathrm{hot}}\)（字节搬运）。\(N\) 次调用均摊

\[ \bar T_{\mathrm{io}}=\frac{T_{\mathrm{io}}^{\mathrm{cold}}}{N}+T_{\mathrm{io}}^{\mathrm{hot}}. \]

常驻的接口是只传 IO 变量。单写者变异（图拷贝、锁内 expand）不要常驻成多线程互抢； 查找可以进 IO 队列，写入仍归一条 owner。

2 · 原子化、连续 stream、递归拆瓶颈

资源 \(\mathcal{R}\) 默认一元：同一资源上两段作业的开区间不相交。 共享主机核 + 共享库（GIL、BBL、图锁）是一条 \(\mathrm{CPU_{sh}}\)，不是两条 CPU。

\[ \mathrm{start}(j)=\max\Bigl(\max_{a\prec j}\mathrm{end}(a),\;\mathrm{free}(r(j))\Bigr), \qquad T=\max_r T_r. \]

连续 stream：资源一空且先行满足，立刻发下一原子，不等整段 tile。 当前 \(\mathrm{bound}=\arg\max_r T_r\)。若该作业仍复合，切开再排。

一次 HTTP POST对这条 HTTP 道：是连接池不拆请求语义
一次锁内图写入对 \(\mathrm{CPU_{sh}}\)：是查找可先离道

3 · 停机 = 理论上效率最优

\[ J=\frac{n}{T}\le J^\star=\min_r\mu_r. \]

当 \(\mathrm{bound}\) 作业不能再切（再切会改硬件/协议量子，或只制造 \(\rho\gg 1\)）， 对这组 \(\mathcal{R}\) 就停。这不是旋钮 Pareto，也不是「算法不能再快」——换算法或换资源集合会重开递归。 挂边 \(t_H\) 进求解器：tile_s[B].H 加进每瓦 hots[k]（易分子约 0.06 s/瓦；M101≈0.2；M089≈1.07）。 它不是 \(|P|\) 的函数，单表值只代表易分子。整树 \(T\) 对不准是正常的——\(n_{\mathrm{iter}}\) 预估不了。 该对的是一轮通量 \(J=n/T_{\mathrm{round}}\)（M098 一轮误差约 7–11%）。 按任务时钟 + 累计 score 改 fill 是后续算法，不写进当前求解器。

展开与 \(B\) · 2026-08-26

\[ t_E=n_{\mathrm{new}}\,\tau,\quad \tau\approx 3.03\,\mathrm{ms},\qquad T=\max(T_G,T_S,T_{\mathrm{cpu}}),\qquad J=\frac{n}{T}. \]

占用 \(T_G^{\mathrm{occ}}=n/\mu_{\mathrm{gpu}}(B)\)。\(\mu_{\mathrm{gpu}}\) 随 \(B\) 升然后饱和。 打分对分子线性时，占用 \(T_S^{\mathrm{occ}}=n\cdot s\) 不随 \(B\)。 求解器的 \(T_{\mathrm{http}}\) 是末次打分结束时刻，不是占用： \(T_{\mathrm{http}}\approx t_G(B)+t_M(B)+n\cdot s\)（整瓦 mat 完才打分）， SCORE_AS_MAT 后近似 \(t_G(B)+t_M(B)/B+n\cdot s\)。 ATTACH_AS_READY 是这组 \(\mathcal{R}\) 上排班的最后一刀：第 1 个分子 score 完立刻挂边， 不再等整瓦。HF generate 仍是一次 kernel。再切只会改 5015 量子或制造 \(\rho\)。 当前 \(T_S^{\mathrm{occ}}>T_G^{\mathrm{occ}}\)，\(J(B)\) 随首瓦 \(t_G(B)\) 弱下降，不是平坦，也不是全程单调升。 \(B\) 小到 \(T_G^{\mathrm{occ}}>T_S^{\mathrm{occ}}\) 时，\(J\) 才随 \(B\) 升到交叉点。

3b · fill 是硬预算，不是 GPU 批

\(B\) = 一次 HF kernel。fill = Dual 一轮最多收几个未问过的 unique INIT，然后 \(k\leftarrow k+1\)。 mssr 封的是轮数。两者一起给出工作量上界。

\[ n_k=\min(\mathrm{fill},|U_k|),\quad n_{\mathrm{work}}\le \mathrm{mssr}\cdot\mathrm{fill},\quad n_{\mathrm{iter}}=\min(\mathrm{mssr},\,\min\{k:|U_k|=0\}),\quad T_{\mathrm{tree}}=n_{\mathrm{iter}}\,T_{\mathrm{round}}. \]

preflight_solver.py 只报一轮 \(T_{\mathrm{round}}(B,\mathrm{fill})\)，\(A=\lceil\mathrm{fill}/B\rceil\)。 整树由 compose_search_volume.py 乘上 \(n_{\mathrm{iter}}\)。 \(n_{\mathrm{iter}}\) 内生：B=4/8 在 fill=32 上 10–11 轮抽干；B=16 跑到 19。 fill∈{16,64} 的 \(n_{\mathrm{iter}}\) 未测，只报一轮和上界 \(20\cdot\mathrm{fill}\)。 删掉 fill 会拆掉 Dual 合同（horizon / COLD_ONCE / mssr），GPU 空着不是理由。

4 · STREAM 甘特（三道目标 vs 整段串行）

同一横轴。红 = GPU generate，绿 = CPU-mat / expand，金 = HTTP。

落地若仍等 _run_forward_* 整段，画的是 A，不能把 \(T_{\mathrm{gpu}}\) 写成 \(A\cdot t_{\mathrm{lane}}\)。

冷路只允许和 GPU 重叠，不和 mat 对打。

5 · Preflight：容量切可行集，再取前沿

旋钮 \(\theta\)（batch、fill、cold、sched、workers）可行当且仅当

\[ V(\theta)\le V_{\mathrm{cap}},\quad M(\theta)\le M_{\mathrm{cap}},\quad F(\theta)\le \Phi_{\mathrm{peak}}\,T(\theta). \]

第三式是下界：实测 \(T\) 已经更长，说明绑在带宽 / 延迟 / 锁，不是峰值 FLOPS。 在可行且已落地的 \(\theta\) 上，对 \((J,-T)\)（可选再加质量）取非支配集，才叫容量 Pareto。 未落地调度画虚线，禁止写进要 apply 的 \(B^\star\)。

求解器：scripts/preflight_solver.py（fill / B / sched）。核分配比另解，见下一节。

6 · 干扰 \(\rho\)、单 worker 原子、核分配比

资源映射写 \(r(j)\)。干扰因子是另一回事：

\[ \rho_{a\parallel b}=\frac{t_a^{\parallel b}}{t_a^{\perp}}. \]

\(\rho=1\) 才许把 \(t_j\) 当常数做 Gantt。\(\rho\gg 1\) 是在抢隐藏资源。 GPU 作业也吃主机核：\(t_G=t_G^{\perp}\cdot\rho_G(\kappa_G)\)。 单 worker 原子 \(t_j^{(1)}\)，\(w\) 个 worker、串行比 \(\alpha\)：

\[ T_j(w)=n\,t_j^{(1)}\Bigl(\alpha+\frac{1-\alpha}{w}\Bigr),\qquad \kappa_G+\kappa_M+\kappa_E+\kappa_{\mathrm{OS}}=K. \]

\(\alpha=0\) 是线性外推，前提是核互斥且无锁。目标仍是 \(J=n/T\)。 枚举整数 \(\kappa,w\)，星标未测之前画虚线。
