拆到不能再拆，再在容量里取 Pareto

常驻消重复 IO。把复合阶段切成原子，在一元资源上连续 stream。 只拆当前瓶颈。瓶颈原子无法再拆时，程序在这组资源上理论效率最优。 硬件 FLOPS / 内存 / 显存决定哪些旋钮可行；可行集上的通量–墙钟前沿才是 Pareto。

最优是一句停机条件，不是一种感觉

理论效率 ≠ 容量 Pareto ≠ 已落地调度。 把非 GPU 工作写进 \(T_{\mathrm{gpu}}\)、或把共享库上的两段活画成可并行，都会造出假前沿。

常驻 原子与 stream 停机 Gantt Preflight

1 · 常驻进程降低多次推理重复 IO

权重、分词器、CUDA context、HTTP session、索引：冷启动 \(T_{\mathrm{io}}^{\mathrm{cold}}\) 每个进程生命周期付一次。 热路径只该剩 \(T_{\mathrm{io}}^{\mathrm{hot}}\)（字节搬运）。\(N\) 次调用均摊

\[ \bar T_{\mathrm{io}}=\frac{T_{\mathrm{io}}^{\mathrm{cold}}}{N}+T_{\mathrm{io}}^{\mathrm{hot}}. \]

常驻的接口是只传 IO 变量。单写者变异（图拷贝、锁内 expand）不要常驻成多线程互抢； 查找可以进 IO 队列，写入仍归一条 owner。

2 · 原子化、连续 stream、递归拆瓶颈

资源 \(\mathcal{R}\) 默认一元：同一资源上两段作业的开区间不相交。 共享主机核 + 共享库（GIL、BBL、图锁）是一条 \(\mathrm{CPU_{sh}}\)，不是两条 CPU。

\[ \mathrm{start}(j)=\max\Bigl(\max_{a\prec j}\mathrm{end}(a),\;\mathrm{free}(\rho(j))\Bigr), \qquad T=\max_r T_r. \]

连续 stream：资源一空且先行满足，立刻发下一原子，不等整段 tile。 当前 \(\mathrm{bound}=\arg\max_r T_r\)。若该作业仍复合，切开再排。

对象原子？再拆只会换 \(\rho\)
一次 HTTP POST对这条 HTTP 道：是连接池不拆请求语义
一次锁内图写入对 \(\mathrm{CPU_{sh}}\)：是查找可先离道
generate+mat+score 整段 forward否必须拆，否则 GPU 空等
同库上的 mat \(\parallel\) expand假原子化测到的是干扰 \(\rho\gg 1\)

3 · 停机 = 理论上效率最优

\[ J=\frac{n}{T}\le J^\star=\min_r\mu_r. \]

当 \(\mathrm{bound}\) 作业不能再切（再切会改硬件/协议量子，或只制造 \(\rho\gg 1\)）， 对这组 \(\mathcal{R}\) 就停。这不是旋钮 Pareto，也不是「算法不能再快」——换算法或换资源集合会重开递归。

4 · STREAM 甘特（三道目标 vs 整段串行）

同一横轴。红 = GPU generate，绿 = CPU-mat / expand，金 = HTTP。

落地若仍等 _run_forward_* 整段，画的是 A，不能把 \(T_{\mathrm{gpu}}\) 写成 \(A\cdot t_{\mathrm{lane}}\)。

冷路只允许和 GPU 重叠，不和 mat 对打。

5 · Preflight：容量切可行集，再取前沿

旋钮 \(\theta\)（batch、fill、cold、sched、workers）可行当且仅当

\[ V(\theta)\le V_{\mathrm{cap}},\quad M(\theta)\le M_{\mathrm{cap}},\quad F(\theta)\le \Phi_{\mathrm{peak}}\,T(\theta). \]

第三式是下界：实测 \(T\) 已经更长，说明绑在带宽 / 延迟 / 锁，不是峰值 FLOPS。 在可行且已落地的 \(\theta\) 上，对 \((J,-T)\)（可选再加质量）取非支配集，才叫容量 Pareto。 未落地调度画虚线，禁止写进要 apply 的 \(B^\star\)。

求解器：scripts/preflight_solver.py。
