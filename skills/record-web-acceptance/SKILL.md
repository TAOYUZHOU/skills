# 录制可跟做、可核验的网页教程

围绕操作人要完成的一件事设计镜头。先在项目里找现有浏览器录制入口、测试素材和回执格式。镜头应同时让观众看到**点了哪里、发生了什么、如何判断成功**。保留应用自己的流程、选择器和业务判据；录制目标由这次委托决定。

## 拍摄

1. 写下每个场景的输入、预期可见结果、能证明结果的业务字段。提前标注来源、样件间是否同一批，以及失败时是要留下故障、追问还是停止。使用本次获准的环境和演示数据；在独立会话中登录，登录凭据留在视频与交付回执之外。
2. 优先运行产品自己的录制脚本。新建 Playwright 录制时，为浏览器上下文设置 `viewport` 和同尺寸的 `recordVideo`，监听本次响应或事件流，再通过页面按钮、输入框和文件选择入口操作。结束时关闭上下文以写完视频。记录每个镜头的实际开始时间，用成片中可见的第一项动作校准时间轴。光标若没有被录下，可将跟随真实点击、移动的指示器叠在页面上。
3. 完整保留发送、等待、进度到结果的过程。对话演示可在同一会话用一句自然语言回指前一轮，验收输出是否引用原样件；换样时把切换动作拍进去。屏幕上若显示“流式”，从真实事件和界面核实究竟是状态更新、文本增量还是两者。剪辑版披露删减、加速或旁白，单轮耗时从真实回执读取。
4. 附件场景拍到选择按钮、待发缩略图或文件名、发送、返回结果和打开后的内容。网页录制常常只拍到系统选择器前后两个状态，交付时注明。应用展示的派生图要和原件、原始读数区分。下载场景实际点击下载：等待浏览器下载完成，检查文件能按所称格式解析，再核对大小、摘要或一项有意义的数据。返回 JSON、聊天内图像、回下载的原件和可下载的新文件分别按它们真实提供的交互验收。
5. 记录实际请求号、最终状态及本次可见的模型、工具、关键结果或产物标识。只保存核对所需字段，剔除令牌、签名链接和私有内容。测试复跑另记请求号和时间，保留首轮结果。模拟素材、离线回放、真实公网回执和实物操作分别标明来源。

## 交付和验收

交付成片和同次去敏回执，保留项目的可复录入口。回执应能将关键点击对应到请求和业务结果。准备字幕时给操作和读结果都留足时间。浏览器自动化模拟的操作与真人试用分别说明。

为离线验片，在回执的 `media` 对象中写入最终成片的 `sha256`（64 位十六进制）和 `duration_s`（秒）。还可登记 `width`、`height`、`nb_frames`、`codec_name`。分章时使用 `chapters` 数组，每项含递增的 `start_s` 与非空的 `title`；时间以**最终成片**为准。导出成片后记录一次这些基准值，复核时使用交付的原回执。

在本机装有 Python 3、ffprobe 和 ffmpeg 时，从本技能目录运行：

```sh
python3 scripts/verify_recording.py tutorial.mp4 receipt.json
```

验片工具比对摘要、时长、可选视频字段和章节，并从头解码主视频及音轨。另播放首尾和各关键动作，核实鼠标、字幕、选中文件、处理图和结果可读，没有被遮挡。验收结论分别写明媒体检查、画面复看和业务核对的结果；只有请求与实际业务回执相符的镜头才能计作该项功能通过。
